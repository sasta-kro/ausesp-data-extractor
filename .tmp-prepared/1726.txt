2.  General Important Definitions

First of all, let me introduce few definitions in order to avoid further
confusions:

[C:\Users\WD\Desktop\Revit-model-2-Bed-Room-House.png]Property (Model
*.rvt) – building, condo unit. The goal of sales agent is to inspect and
sell a property. In this project property will be also represented as
Autodesk Revit Model *.rvt. which is a fully virtual representation of a
property that contains all information about it.

Figure 2.1 Example of Revit Model

that describes a property (Autodesk Revit Model *.rvt). In general, they
show which equipment the property (model) has, their materials and the
other types of constructional features.

[]

Figure 2.2 Example of fields in Autodesk Revit Model

Inspection – the presale process in which a sales agent and a customer
who intend to buy a property are inspecting the fields of that property
in order to find potential problems of fields.

Issue – the problem with the fields of a property that was detected
during the presale inspection. Issues are discovering by a customer and
must be described by a sales agent and submitted into the system for
further investigation and fixing.

Issue Report – the pdf document that automatically created by system
after the presale inspection. This document will contain information
about customer and conclusion about inspection.

4.  Statement of the Problem

Currently, property market is highly competitive. Every construction
company intends to provide better way to satisfy potential buyers. There
are many ways to approach this goal:

- Better service and customer support

- Higher quality of materials

- Extended guaranty

- Units customizations

- Various bonuses

- Discounts

One of the easiest and, more importantly, more cheapest ways is
providing better service and customer support. As long as the scope of
this project is presale inspection I am going to concentrate only on
this part of customer service.

When we think about traditional approach of presale inspection we may
face these difficulties:

- Pre inspection preparation – before the actual inspection the agent
  has to prepare documentation about the project. This task requires
  communication with the project construction and massive project
  documentation management.

- Inspection process – during this process the sales agent has to
  inspect property according to the prepared documentation in the first
  step. All process is manually paper based as a result the inspection
  is longer. Moreover, in case of occurring issues with the property the
  sales agent has to prepare documents describing them and in the end
  submit those document for the contractor for investigation and fixing.
  The progress of fixing issues is closed or at least associated with
  difficulties for the customer.

- After inspection report – after inspection the sales agent has to
  prepare document that describes inspection process and issues if they
  were found for the customer. This takes time and effort.

- Human factor – because of human involved in many processes it is
  higher risk to make mistake of forger about something important. It is
  not bad, but it is fact that humans make mistakes.

- Difficulties with the paper based documentation – this is common
  drawback for all types of paper based documentation. It takes space,
  it is hard to find something, it may be easily destroyed.

5.  Objectives

The goal of this project is minimize problems that were described in
previous section and to make process of presale inspection smooth and
seamless.

The main objectives of this project can be described as follows:

- To develop a system that will allow to simplify the pre inspection
  preparation utilizing data from Building Information Modeling (BIM).

- To maintain sales agent information.

- To assign specific data for the inspection for the sales agents.

- To provide convenient way of inspection process via web application.

- In case of issues to simplify the issue creation and maintenance.

- To keep issues information of related models.

- To generate presale inspection reports.

- To inform customers about updated related to their units.

6.  User Requirements

This system will have two types of accounts: Administrator and Sales
Agents.

The administrator account only one and created “out of box” and
specialized on the managing of whole system.

The sales agent accounts will be created by administrator and their main
goal is presale inspections.

The user requirements are considered as follows:

Administrator:

- Creating, and managing sale agents accounts.

- Importing information from the models (Autodesk Revit *.rvt) from
  Autodesk BIM 360 Document System.

- Specifying the fields of the model that has to be checked during
  presale inspection by sales agents.

- Assign models to the sales agents.

- Review results of all presale inspections completed by sales agents
  and download reports.

- Review of all issues that were created during inspections.

Sales Agent:

- Update his own profile.

- Conduct inspections of assigned models.

- Create issues and attach photos to them.

- See his previous inspections results and download reports.

- See issues initiated by him.

7.  Scope of the Project

The system functions and features will include the following:

- Sales Agent Management
  The administrator will be able to create sales agent accounts by
  specifying their email, password, first and last name. The
  administrator will be able to edit and remove accounts. Also,
  administrator will be able to assign imported models for sales person.
  This will allow sales person to inspect this model.

- Models import
  The administrator will be able to import models data to the system via
  Forge API, as well as delete those models from the system. I assumed
  that models must be prepared by contractor and uploaded to the Project
  Files Directory in the Autodesk BIM 360 Document system.
  []

  Figure 7.1 The folder for Revit Models in Autodesk BIM 360

- Fields management
  The administrator will be able to select the fields of the model that
  sales agent has to check during presale inspection. The fields must be
  extracted from the Revit file (that uploaded to the BIM 360) via Forge
  API. I assumed that model must be properly prepared by constractor.

- Inspections.
  The administrator will be able to check all inspection in the system.
  The system must provide convenient way for the sales agent to conduct
  model inspection. Sales manager has to be able to go through every
  field and confirm that it is ok or create issue with description about
  this issue.

- Issues.
  The administrator will be able to check all issues in the system.
  All confirmed issues with photos will be committed to the BIM 360 via
  Forge API. I assume that issues fixing and status updates will be done
  by constructor. The system will automatically update the issues
  statuses from the BIM 360.

- Benefits Analysis

  a.  The system will help to improve quality service for the property
      sales process.

  b.  The pre inspection process will be simplifies by automatized
      extraction fields from the Revit models. And once administrator
      selects fields, the pre inspection process will be done instantly.

  c.  The system will allow to manage access rights for the sales
      agents. They will have access to the models that allowed by
      administrator. Security will be impoved.

  d.  The inspection process will be simplified for the sales agent. The
      interface will lead agent though all fields and will not allow to
      complete inspection without checking all fields.

  e.  The sales agent will be able to create issues directly from the
      inspection process. The newly created issues will be transferred
      to the BIM 360 system automatically.

  f.  The system will track the updates on the issues and notify all
      people involved in it via email in case of updates of progress
      changes.

  g.  The system will create inspection reports automatically once
      inspection is done and send them to the email of customer and
      sales agent. This will allow to clarify the situation in case of
      various misunderstandings after inspection.

The next difficulty was with attaching photos to the issues. This
process requires several steps before file can be bounded with the
issue:

a.  Step 1: Finding the hub that has a project

b.  Step 2: Finding the target project

c.  Step 3: Creation of a storage location

d.  Step 4: Uploading a file to the storage location

e.  Step 5: Creating the first version of the uploaded file

f.  Step 6: Finding the issues container of the project.

g.  Step 7: Finding the target issue.

h.  Step 8: The assigning the uploaded file as an attachment of the
    issue.

It looks a lot but some of the steps can be avoided, for instance I save
issue id and issues container id in the local database so steps 6-7 can
be skipped. Also as long as this project has target of only one project
in BIM 360 Doc steps 1-2 has to be done only once during development and
then the project id will be stored in the application configuration.
However, steps 3-5 and 8 cannot be omitted and has to be done for every
file.

But this is the typical process, the issue was in confusion with
documentation where was an inaccuracy with extension types for API
request in step 5. In documentation was example that uses "type":
"items:autodesk.core:File", but request with this type will end with API
responce:

"status":"400","code":"BAD_INPUT","title":"One or more input values in
the request were bad","detail":"Request input is invalid for this
operation."

issue_status – stores information about issue statuses. Predefined
statuses:

- Unconfirmed – issue just was created. It requires to be approved by
  administrator and sent to the BIM 360 Issues.

- Pending – issue was approved by administrator and sent to the BIM 360.

- Resolved – issue was closed in BIM 360. Should be resolved.

- Rejected – issue was rejected by administrator. Maybe it is a feature
  not an issue or some misunderstanding occurred. It will not be sent to
  the BIM 360.
