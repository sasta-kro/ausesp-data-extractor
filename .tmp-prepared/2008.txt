Abstract

Nowadays there is a huge rise in the number of online games, as
technology is getting better the games are starting to look more and
more realistic. This brings a huge problem for people who cannot upgrade
their computers every time a new game release that requires more ram or
video memory. Then there is the problem of hardware compatibility and
driver’s problem that can be hard for a person with a less technological
background. So, at Cloud Café we provide an alternative to getting your
computer and keeping it up to date. We provide a cloud gaming platform
where users can play games on any Mac or Windows computer that can run
Microsoft teams.

We accomplish this with AWS provided cloud compute instances and allow
users to play games over the network. This has been made possible due to
the increasing internet speeds all over Thailand as well as the low
latency RDP provided using Parsec. At Cloud Café we make the experience
of starting a game on an AWS instance all done in a single click
therefore making the complex process fully automated.

Overview of Cloud Café

Cloud Café is a software that will make playing games as easy as
watching movies on streaming platforms. In the present date. The only
way to play a top-level game or in another name is called “AAA listed
game “. You need to spend around 20 to 30 thousand baht to just to be in
entry-level hardware that top-level games are just playable. But not
just that,

So, the method that Cloud Café is using to solve this problem is by
combining Cloud computing technology with streaming technology that lets
every game that real-time communication will be required happened.
Because gaming is not like watching a movie on a streaming platform,
movies nature of the use is that it doesn’t need input from the user in
real-time to decide on what happens next. But on the other hand, games
don’t work like that. Games do require your real-time input to decide
what happens next.

Therefore, in Cloud Café you can play games by don’t need the best
hardware to run AAA games. Cloud Café lets you choose the game that is
installed in our cloud and you can play right away. Last, Cloud Café
will do all of the auto-saving of the progress you make in the game you
can start right away from where you left it. All of this just requires a
computer with either a Windows OS or Mac OS and a minimum internet speed
of 30 Mbps with minimal latency.

What is Electron?

Electron is a framework that supports the development of desktop
applications using web technologies such as the Chromium rendering
engine and the Node.js runtime. Supported operating systems include
Windows, macOS, and Linux. Chances are you have used at least one of
these applications, which were all developed using Electron: Visual
Studio Code, Slack, Discord, Skype, GitHub Desktop, Twitch. So, the
platform was famous and provided us with the native capabilities we
require to perform the necessary tasks.

What is Electron.Net?

Electron.NET is a wrapper around a "normal" Electron application with an
embedded ASP. NET Core application. It is an open-source project that
allows .NET developers to invoke native Electron APIs using C#.
Electron.NET consists of two components:

1.  NuGet package that adds Electron APIs to an ASP. NET Core project

2.  .NET Core command-line extension that builds and launches
    applications for Windows, macOS, and Linux platforms.

Electron.NET requires the prior installation of the following software:

- Node.js

- .NET Core 3.1

This was a good fit for our project as our team had previous experience

1.1 EBS: An Amazon EBS volume is a durable, block-level storage device
that you can attach to your instances. After you attach a volume to an
instance, you can use it as you would use a physical hard drive. EBS
volumes are flexible. You choose it every time, otherwise, your OS won't
launch.

In this option, you can choose to add storage as well for you. For our
design, we went with one storage that is in the size of 500 GB. The
reason is we need to store about 4 AAA games, and, the average game size
of those is around 100 GB per game. EBS cost will charge excluding the
instance cost.

After you instance you are launch, you as enter it though Parsec then
you install all the game that you must choose to be in this EBS.

1.2 Snapshot: An EBS snapshot is a point-in-time copy of your Amazon EBS
volume, which is lazily copied to Amazon Simple Storage Service (Amazon
S3). In simple language is, you can create a point-in-time save for your
hard drive. For us, this is required because we needed to save games
into a hard drive so that we don’t need to install it again. And,
another advantage is to make many copies of snapshots into EBS in order
to be connected with other instances.

1.3 AMI: An Amazon Machine Image (AMI) provides the information required

        id will automatically be shared to Taranjit and will show up as

    c.  Tfa: Two-factor authentication is required by parsec to prevent
        bots and other misuses of the RDP.

: Conclusion 

Yes, we have been able to connect the client to the host on request. But
the current solution is incomplete as it overlooks the cost that is
being used to launch the AWS instances therefore is currently not being
the best option to use as a daily driver. It also faces several other
issues such as.

1.  To obtain a session id, we need to use the backup tfa codes which
    are generated on Parsec website. We can only generate 10 backup
    codes at a given time one’s new codes are generated the old codes
    are no longer valid and one code can only be used once. This is a
    huge obstacle as this means that at a given time there can be only
    10 players.

2.  The AWS instance takes a lot of time to launch and to perform the
    setup. This considering from an end-user standpoint can be
    considered as bad UX.

3.  There is no queue system during the launching of a new instance or
    connecting a user to an instance. This leads to problems such as one
    user being connected to an instance launched by another user.

4.  The limited amounts of games are also a huge issue as to get a
    bigger game library we need to pre-install a lot of games on the AWS
    instance this requires a lot of capital. And will not be viable
    unless there are a lot of paying users.

 Future works

The project currently is just a trial run to get the necessary expertise
in order to develop a better experience for the end-user. So, here are
the features or changes that we might do in the foreseeable future.

1.  Redesign the User interface for the native application by moving the
    features such as register, edit account detail, to the website
    instead of the native application.

2.  Creating a website to download the latest update for our
    application. And to purchase in-app currency which will be used to
    play games.

3.  Adding time-related features to the native application to keep track
    of in-app currency.

4.  Creating a way to add payment on the website to buy currency.

5.  Increasing the security of the native application to prevent misuse
    of the features.

6.  Adding a queue mechanism while launching a new AWS instance in the
    server-side implementation.

7.  Separating the Native app and Server-side to divide the load and
    optimize the speed of the application.

8.  Updating the user interface to match a native application style.

9.  Trying out Moonlight which is a Parsec alternative but is open
    source. To massively reduce our cost.

10. Switching to AWS spot instance to further reduce our costs down to
    an affordable price.
